# Conventions

## Naming Conventions
here we used this-hypenated-syntax to name files.
Every Letter that we want to a seperate letter needs to be hypenated seperately.
for instance if "L Hopital Rule" is what you want to see as the title of your topic then you need to name it as "l-hopital-rule.md" and not as "~~lhopital-rule.md~~".

## Content Organisaton

`content` folder is probably the folder that you will use the most. Therefore it is a must to understand it.

this is the project tree of the content folder:

```
content/
├── _index.md                # Main homepage content
├── Chemistry/
│   └── _index.md            # Chemistry section
├── Editorial/
│   ├── add-latex-support.md # Example page
│   └── _index.md            # Editorial section
└── Math/
    ├── _index.md            # Math section
    └── l-hopital-rule.md    # Example page
```

Every subject's name is capitalised while every topic is written in lowercase.

# How to maintain documentation

A good documentation not only helps an outsider understand your code better and get on board faster but also keeps the team updated about the changes that were made and why.

Therefore it is a courtesy to write down-in the editors' section or README.md files or whereever applicable- what you did and why when ever you add a new feature, change the look and feel, etc.

however it is not required when you add a blogpost or contribute to notes. It isonly needed when you handle code.
